# Canon

## Name

**AFTER THE LAST SERVER**

Subtitle:

> An archive of machines still waiting.

## Subject

The museum is about interfaces that outlived the worlds they expected to reach.

The interesting object is not “old software.” It is the residual relationship between a machine and an absent human system.

A disabled service can leave behind:
- a reconnect button
- a presence indicator
- an update mechanism
- a login form
- a map
- a friends list
- a queue
- a status page
- a launcher
- a promise

The interface may still know exactly what should happen next.

Reality no longer agrees.

## 01 — RECONNECT

A nearly empty room.

One ordinary application window.

`Disconnected`

A visitor presses `Reconnect`.

The machine attempts the old ritual faithfully.

`Connecting…`

Then:

`Server not found.`

Only after failure does the label become visible:

> The interface kept waiting after there was nobody left to wait for.

The failure is the exhibit.

## Future rooms

Names are provisional until built.

- **PRESENCE** — contact lists, away states, friends who can never come online again.
- **UPDATE** — software still asking servers for a newer version that will never arrive.
- **WORLD MAP** — maps of persistent worlds after persistence ended.
- **QUEUE** — systems designed to make people wait for an event that can no longer occur.
- **SIGN IN** — authentication as a door preserved after the building is gone.
- **PROMISED FUTURES** — interfaces from systems that expected to become normal life and did not.

## Collection ethics

When real historical software is used, preserve provenance.

Prefer:
1. original documentation and publicly available archival material;
2. screenshots/assets used with permission or under an appropriate license;
3. faithful reconstruction when direct redistribution is not appropriate.

Do not silently present reconstruction as an original artifact.
Do not romanticize the communities that disappeared; document them.

## Non-goals
